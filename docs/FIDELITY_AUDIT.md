# Mary-O Lite: source-fidelity audit, October 2026

This is a checked comparison with the supplied Ambition source snapshot, not
an assertion of feature parity. Original source assets stay in SVG, LDtk, or
Python; generated PNG and WAV files are never tracked.

## Authored LDtk coverage

| Authored content in the eight main rooms + warp | Count | Lite status |
|---|---:|---|
| Player starts | 9 | Loaded |
| Enemy spawns | 120 | All eight source character IDs are recognized; simplified AI |
| Mary-O blocks | 478 | Brick, question, hidden, power, plank represented |

This table covers map objects, not the larger collection of resources in the
Ambition engine. Some scene content is generated by Ambition's runtime and is
not recorded as LDtk entities.

## Fixes in this pass

1. **Rotating Fire Bars:** Original `path_points` polygons and `path_speed`
   values are loaded per orb, sampled by world-time distance, and used for
   *both* collision and the source-painted FireOrb position. Rotation follows
   the ordered clockwise/counterclockwise paths in LDtk. Each room saves its
   hazard clock across backtracking. Sources:
   `game/ambition_demo_mary_o/tools/mary_o_level.py`,
   `targets/props/entities.py::fire_orb`.
2. **Snake Plants:** Positioned relative to the top rim of their pipe, with
   the authored 330-tick hide/rise/expose/retract cycle, 36-tick travel and
   40 px shy reach. The original multi-part painted body is clipped at the
   pipe mouth, and pipes are composed in 16-pixel-high sections in front of
   the plant rather than stretched into a single tall headpiece. Stomping
   a visible plant hurts Mary-O; it is not a safe landing. Sources:
   `game/ambition_demo_mary_o/src/plant.rs`, `assets/data/mary_o_rules.ron`.
3. **Moving platforms:** Authored `sweep_dx`, `loop_dy`, `loop_min_y`, `speed`
   determine ferries and lift chains. A constant-speed triangle sweep or
   shaft wrap replaces the former generic sine-wave motion. Players ride
   a platform without being teleported during a lift's wrap.
4. **Missing source-painted enemies:** The paper-plane and Cartesian-plane
   flying snake sprites are now generated from the original Python character
   art. This removes the generic wing-and-ellipse fallback for these 17
   placements. Source:
   `targets/characters/_snakes_on_planes_common.py`.
5. **Projectiles and animation:** The FireOrb painter, VoidOrb painter and
   coconut artwork were ported from original source and generated into the
   same binary cache. Swallows throw coconuts, Void Lizards shoot void orbs,
   and sliding Solid Snake shells keep their boxed animation. Source:
   `targets/props/entities.py`, `targets/props/coconut.py`,
   `targets/characters/solid_snake.py`.

## Still different from Ambition

- **Render/camera:** source tiles and sprite artists are reused, but full
  parallax sets, authored camera-zone cinematic zoom, shader lighting and
  world presentation are not yet matched. No shader dependency is planned.
- **Enemy gameplay:** Original characters are drawn, but several Rust brains
  use additional patrol, attack, perception, retreat and knockback phases that
  have not been fully reproduced; the Solid Snake's timed retreat/peek cycle,
  the swallow tracking rule and Void Lizard boss tactics remain simplified.
- **World interactions:** source blocks and pipes are represented, but pipe
  transitions, stage clear animations, scoring details, climb/swim gameplay,
  and all sound cues do not have full source parity.
- **Game feel:** The basic motion tunings are ported, but collision contact
  ordering, enemy timing and camera smoothing have not been compared in a
  running Pygame window against the Rust build.
- **Art verification:** The Pillow preview is a contact sheet of generated
  source frames. It is not a screenshot of Pygame in motion. Graphical
  playtesting is necessary before claiming the rendition looks exact.

## Verification

To inspect the actual regenerated poses and Fire Bar rotation without Pygame:

```bash
python tools/preview_fidelity.py
```

This writes two ignored PNGs in `assets/generated/`. Rebuild with
`python main.py --build-assets`, run headless tests with
`python -m pytest -q`, and start the game with `python main.py`. The first
full build is CPU-intensive because several original enemy painters render
supersampled frames; subsequent runs reuse the cache.
